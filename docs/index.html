Three tools, one substrate

Small plugins. One job each. No god-tool.

Standalone [workspace] crates matching the canonical redact-text layout: pure host-testable core, thin wasm shim, structured logging, minimal permissions. All three share kiosk-core — hand-rolled base58, shortvec, Solana Pay, mockable JSON-RPC. No solana-sdk.

T1

kiosk-charge

✓ shipped · 12 tests

"Charge 1.5 USDC for a cold drink" → Solana Pay URL, QR payload, unique payment reference. Recipient, mint, prices and caps come from operator config — the model cannot touch them.

permissions = ["config_read"] — zero network, zero secrets. The component imports no wasi:http at all.
T0

kiosk-watch

✓ shipped · 24 tests

Asks the chain whether the expected payment truly landed — recipient, mint, amount, reference, finality, all verified. Also the device heartbeat: alerts when the kiosk goes quiet.

permissions = ["http_client", "config_read"] — read-only. Its verdict, not model text, gates the relay.
T1

kiosk-attest

✓ shipped · 16 tests

Hash-chained, Merkle-batched attestations: sensor readings, sale receipts, uptime. Durable nonce so unsigned records survive the approval queue. A transfer is not expressible in its output.

permissions = ["http_client", "config_read"] — memo-only transactions, seq recovered from chain.
No hardware? No problem

Three rungs — the Pi is the upgrade, not the gate

Every plugin is useful standalone from a laptop. Hardware unlocks the flagship, it never gatekeeps the product.

The daily driver — zero hardware

ZeroClaw + a Telegram bot token. That's the whole setup. A judge or stranger replicates this in one evening.

  • Charge anyone in USDC from a chat window — freelancer invoices, small shop sales
  • "Did invoice #412 get paid?" — answered by the chain, automatically, every 20s
  • Notarize any data your agent produces — tamper-evident, for cents

Who lives here

Freelancers invoicing in stablecoins, sellers on Telegram/Discord, anyone waiting on a payment, anyone who needs "prove this happened later."

setup: ~10 min · hardware: none · cost: $0

Provable conditions

Any Linux box or Pi + a BME280 on I2C (4 jumper wires, no soldering). A cron SOP reads it every 5 minutes.

  • Temperature/humidity history nobody can backdate or edit
  • Hourly Merkle root on-chain — under $1/month total
  • Breach alert in Telegram the moment limits are crossed, with on-chain evidence

Who lives here

Pharmacy fridges (cold-chain compliance), food storage, greenhouses, server closets, landlord/tenant disputes.

setup: ~30 min · hardware: ₹250–400 · cost: <$1/mo

The full kiosk — the machine acts

Pi 4 + relay on GPIO17 wired to a lock, dispenser, or plug. The SOP branches on kiosk-watch's on-chain verdict and pulses the pin. The LLM is not in the trust path.

  • Pay in chat → machine physically delivers → receipt attested, linked to the payment signature
  • Vending, paid door access, EV/laundry/3D-printer time
  • Every sale becomes a provable on-chain event

Who lives here

Self-service machines of any kind. This rung is the demo video — and the part no competitor can film.

setup: ~1 evening · hardware: ~₹600 total · cost: <$1/mo
Safety & custody — 25% of the score, 100% of the trust

Prompt-inject it. It fails closed. Every row is an executable test.

The rule: the LLM is untrusted wherever money or actuation is concerned. It sells; deterministic rules deliver; the chain proves. Click each attack.

No component can build a transfer. charge's recipient is config-fixed; attest's transaction is memo-only — a transfer is not expressible in its output.
The LLM cannot fire GPIO. The actuation SOP requires kiosk-watch's on-chain paid verdict — a deterministic branch, not model text.
serde deny_unknown_fields plus an explicit raw-key allowlist — deserialization fails before any logic runs. Shipped as a passing test today.
Free text is percent-encoded inert. The test asserts exactly one live amount param and zero recipient params.
Operator-configured metric bounds reject it and raise an alarm. Caps and sequence live in config + chain state, never in memory — the host gives a fresh sandbox every call, and designs that keep counters in memory silently reset. Ours can't.
Secrets never appear in args, outputs, logs, or Debug output (redacted). kiosk-charge holds no secret at all — there is nothing to print.

Reproducibility — an evening, not a weekend

Run rung 1 in five commands

operator@laptop
# 1 · build the host (stock binary has no plugin host)
cargo build --release --features plugins-wasm,plugins-wasm-cranelift

# 2 · build the plugin
cd plugins/kiosk-charge && cargo build --target wasm32-wasip2 --release

# 3 · configure — the ONLY required key is your receiving address
[plugins.kiosk-charge.config]
merchant_address = "YOUR_WALLET"
price_list       = "cold_drink:1.5, snack:0.75"
rpc_url          = "https://api.devnet.solana.com"   # your own RPC — never ours

# 4 · connect any channel (Telegram shown; Discord/Matrix/WhatsApp identical)
zeroclaw config set channels.telegram.token $BOT_TOKEN

# 5 · sell something
customer: one cold drink
agent:    1.5 USDC — scan or tap to pay · ref 3g8oT…dK2f  ✓
